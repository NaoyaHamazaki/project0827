# チャット設定：AIマスキング機能 仕様案（検討中・未実装）

作成日: 2026-11-07
ステータス: **アイデア段階**。管理者メニューの「チャット設定」にはタイトルのみ表示しており、
本ドキュメントに記載の機能はまだ実装されていない。

## 1. 背景・目的

チャット機能（`backend/chat/`）に蓄積されるメッセージには、個人情報や取引先情報など、
漏洩時の影響が大きい内容が含まれる可能性がある。これを人手だけでチェックするのは
現実的でないため、AIによる定期チェック＋自動マスキングの仕組みを検討する。

## 2. 機能概要（2つ）

### 2-1. チャット履歴AIマスキング（オン／オフ切り替え）

- 管理者が「チャット設定」画面でオン／オフを切り替えられる機能として想定
- オンの場合、チャットテーブル（`chat.Message`）の内容を定期的にAIがチェックし、
  漏洩した場合の影響が大きいと判断した情報は自動的にマスキング（伏せ字化）する

### 2-2. マスキング判断（人による確認）

- AIが「マスキング対象かどうか判断がつかなかった」メッセージについては、
  人間側が確認してマスキング対象かどうか判断できるようにする
- 日常業務でチャットを使う担当者が、確認待ちの一覧を見てマスキングするかどうかを判断する運用を想定

## 3. データモデル変更案

`chat.Message` にステータス用カラムを追加する。

| 値 | 意味 |
| --- | --- |
| ブランク（空） | 未チェック。AIチェックの対象になる |
| 要確認 | AIが自動判断できず、人による確認待ち |
| 確認済 | チェック完了（AIが安全と判断／自動マスキング済み／人が確認済み、のいずれか） |

- **移行時の初期値**: 本機能の実装時点で既に存在するメッセージは、すべて「確認済」として
  扱う（過去メッセージを遡ってAIチェックの対象にはしない）
- 新規に投稿されるメッセージは「ブランク」から始まり、後述のバッチ処理でチェックされる

## 4. バッチ処理（AIチェック）の対象条件

定期実行するチェック処理は、以下の両方を満たすメッセージを対象とする。

1. `created_at` が、チェック処理の実行時刻から **24時間以上前** であること
   （投稿直後のメッセージはまだ会話が続いている可能性があるため対象外とする）
2. ステータスが「ブランク」であること

対象メッセージに対してAIが内容を判定し、次のいずれかに遷移させる。

- 漏洩時の影響が大きいと判断 → 自動マスキングを行い、ステータスを「確認済」にする
- 安全と判断 → ステータスを「確認済」にする
- 判断がつかない → ステータスを「要確認」にし、人による確認を待つ
