# 運営者向け資料（Webページ）構成案

作成日：2026-09-05
目的：[運営者ヒアリングシート](運営者ヒアリングシート.md)で損失・手間の実態を確認できたあと、「じゃあ具体的に何が変わるのか」を短時間で見せるための資料。**まだ「見せて終わり」で構わない前提**（作り込みすぎない、1回の会話で決着をつける方針）。

## 前提・方針

- ヒアリングの結果次第では、この資料自体を使わない（見送り）こともあり得る。ヒアリングが終わってから作り込みに入る。
- ページは1枚もの（スクロールのみ、タブや複雑な導線は作らない）。
- 「売り込み」ではなく「今の紙管理をそのまま置き換えるとこうなる」を見せることに徹する。発展性の話は最後に一言添える程度に留める。
- 専門用語（SecurityCard、CardLoan等の実装名）は出さない。運営者に伝わる言葉（「貸出カード」「保持者」など）に置き換える。

## 見出し構成（上から順）

### 1. フック（今の困りごとの言語化）
- 見出し例：「紙の貸出記録、こんなことになっていませんか？」
- 受付で聞いた実態（会員証を受け取り、セキュリティカードを渡し、番号を手書きで記録）を1枚のイラスト or 簡潔な文章で再現し、「これ、うちのことだ」と思わせる導入。
- ここで数字を入れる余地があれば（ヒアリングで聞けた場合）、1日の貸出件数などを添えて「地味に手間がかかっている」ことを可視化。

### 2. 今の運用の限界（1点に絞る）
- 引継ぎメモの通り「記録はできても、今何が起きているかは分からない」の一点を突く。
- 箇条書き3つ程度に抑える：
  - 今、何枚のカードが外に出ているか、パッと分からない
  - 誰が返し忘れているか、営業終了後に気づく
  - 過去のトラブル（紛失・行方不明）を調べようとすると紙をめくる必要がある

### 3. 置き換えるとこうなる（Before/After）
- 左右比較 or Before/After形式のシンプルな図。
- Before：会員証受け取り→セキュリティカードを渡す→紙に手書き→(あとで見返す時は紙をめくる)
- After：会員証をスキャン→貸すカードを選ぶ/スキャン→自動記録→(画面で今の状況が一覧できる)
- 「受付の操作はほぼ変わらない」ことを明記し、導入ハードルの低さを伝える。

### 4. 画面イメージ（1〜2枚のスクリーンショット程度）
- 実装済みの「セキュリティカード管理」画面と「在室・ログ管理」画面（未返却フィルタ付き）のスクリーンショットを軽く添える。
- キャプションは機能名の羅列ではなく、運営者の言葉で一言説明（例：「今、外に出ているカードと持っている人が一目で分かります」）。

### 5. これから広げられること（発展性は最後に軽く）
引継ぎメモの「発展性の提案の軸」を、売り込み口調ではなく「今後、必要になったら」というトーンで3〜4行程度：
- 未返却のまま営業終了時刻を迎えたら知らせる
- 紛失・破損の履歴が残るので、再発行コストの根拠にできる
- 拠点が増えても同じ仕組みで管理できる

### 6. クロージング（次のアクションを軽く提示）
- 「まずは今の運用のまま、試験的に使ってみることもできます」程度の低圧な一言。
- 具体的な金額・契約条件などはこの資料段階では出さない（1回の会話で決着をつける方針のため、運営者の反応を見てから詰める）。

## 使わないこと（あえて外す）
- 料金プラン、契約形態の詳細
- FELDNAとの関係や会社としての実績アピール
- 複数拠点展開のロードマップの詳細（仮説段階のため、匂わせる程度に留める）
- 導入スケジュールや工数の見積もり
