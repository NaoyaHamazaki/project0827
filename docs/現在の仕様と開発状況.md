# 現在の仕様と開発状況（提案資料作成用）

作成日: 2026-11-08
対象: `main` ブランチ（本番デモ: Railway）
目的: ユーザー向け提案資料を作る際に、「今何ができて、何がまだできていないか」を確認しやすくする。
動作確認の根拠は `docs/テスト仕様書.md`（2026-09-17実施）と、今回のセッションでのブラウザ確認。

> 資料に載せる際の注意: 「実装済み」と「開発予定／未対応」を混同しないこと。
> 特に会議室の間取り図は**ベータ版**、チャットのAIマスキングは**構想のみ**。

---

## 1. システム概要

コワーキングスペース向けの **受付・入退室管理** と **セキュリティカード貸出管理** に、
会員向けの **チャット・会議室予約・飲み物注文** を加えたWebアプリ。スマホ・PCのブラウザで動く。

| 項目 | 内容 |
| --- | --- |
| 利用者の種類 | 管理者（運営スタッフ）／ユーザー（会員） |
| 画面言語 | 日本語（英語切替の仕組みあり。英訳は一部のみ） |
| 動作環境 | ブラウザ（PC・スマホ）。インストール不要 |
| 公開状況 | Railway上にデモ公開（共有パスワードのゲート付き） |

## 3. 主な機能の詳細

### 3-1. 入退室とセキュリティカード貸出
- 入力方式は QRコード（カメラ読取）／番号入力／バーコード・ICカードから、管理者が受付設定で選ぶ。
- 入室時にセキュリティカードを選ぶ画面が出る。「選んで貸出」ボタンで確定。貸出なしの選択も可能。
- 退室時は、その会員が借りているカードを自動で返却扱いにする（再入力不要）。
- 貸出中のカードは二重貸出できない。24時間を超えて在室が続くと一覧で赤く強調。
- プランごとに月間の利用上限時間を設定でき、残り時間を表示する。
- ICカードリーダー連携（Sony RC-S380）は**ローカルPCに接続した場合のみ**動作。Railway上のデモでは使えず、QR／番号入力で代替。

### 3-2. 会員の新規登録（3通り）
| 方法 | 流れ |
| --- | --- |
| フォームに入力 | 管理者が氏名・所属企業・メール・プラン・カードID・パスワードを入力。カードIDと初期パスワードは自動生成ボタンあり。確認ダイアログ後に登録 |
| QR表示 | 管理者が画面にQRを出し、本人がスマホで読んで自分で入力 |
| URLをコピー | 同じ内容のURLをメール等で本人に送る |

- QR／URLのリンクは**24時間有効・1回限り**。使用済みや期限切れでは登録できない。
- 登録すると、会員情報とログインアカウントが同時に作られる。

### 3-3. 会議室予約と注文
- 予約: 終了が開始より前、予約不可の会議室への予約はエラーで弾く。キャンセルは本人または管理者。
- 注文: 管理者側の注文一覧にリアルタイムではなく**画面を開いた時点の内容**が出る（自動更新・通知は未実装）。
- 注文の受付可能時間（開始・終了時刻）を過ぎると、注文画面は「受付時間外」表示になる。
- 会議室・メニューには、複数拠点運用に備えた「拠点ID」欄をデータ上だけ用意済み（画面では未使用）。

### 3-4. 間取り図（ベータ版）
会議室設定 → 「間取り図を作成する」から入る。

- **描く**: マス目をクリック／ドラッグして範囲を選び、「描画」で多角形に自動変換（斜めの辺も作れる）。
- **配置**: 図形を「この図を使用」でキャンバスに追加。ドラッグで移動（1マス単位）。名称は図形の大きさに合わせて自動で縮小。
- **拡大縮小**: 選択すると透明な外枠と右下のつまみが出て、ドラッグで拡大縮小（Shiftで縦横比維持）。
- **辺の長さ**: 図形にカーソルを合わせると各辺のマス数を表示（同じ大きさの部屋を作る目安）。
- **会議室との紐づけ**: 図形に会議室を紐づけ、「表示」モードでクリックすると予約状況つきの詳細を表示。
- **3D表示（試用）**: 高さを入力すると立体で表示し、回転・拡大ができる。初回のみ読み込みに数秒かかることがある。
- **保存**: 「配置を保存」で保存。描画した図形は履歴に残り、「この図形を使用」で再利用できる。

### 3-5. チャット
- 管理者とユーザーの1対1。太字（`**文字**`）、いいね、未読数のバッジ、日本語入力の変換確定では送信されない配慮。
- 会話は参加者本人しか見られない（管理者でも第三者の会話は見られない）。自動テストで確認済み。

## 4. セキュリティ・運用（提案資料で聞かれやすい点）

詳細は `docs/セキュリティ対策.md`。

**実施済み**
- ログインはトークン認証、パスワードは暗号化して保存、通信はHTTPS
- 管理者／ユーザーで操作できる範囲を分離（会員管理・設定・各種一覧は管理者のみ）
- QRコードは5分で失効。会員登録リンクは24時間・1回限り
- 本番で初期の秘密鍵のままでは起動しない安全装置、秘密情報は環境変数で管理
- 過去にソースへ直書きされていた外部サービスのトークンは、失効・再発行・環境変数化済み

**未対応（正直に伝える点）**
- ログイン試行の回数制限、セキュリティヘッダーの追加、依存パッケージの定期点検
- 管理操作の監査ログ（誰がいつ何を変えたか）
- データベースのバックアップ設定の確認
- 管理画面（/admin/）の公開範囲の見直し、Webhook宛先の制限
- 大手SaaSと同等の水準とは言えない。デモ・検証段階の位置づけ

## 5. 開発中・未実装・既知の課題

| 区分 | 内容 |
| --- | --- |
| 構想のみ | チャット履歴のAI自動マスキング、人による確認キュー（仕様案: `docs/チャット設定_AIマスキング仕様案.md`） |
| 未実装 | ユーザー画面の「設定」、設定＞一般の項目 |
| 未実装 | 権限の3段階化（運営／会員企業の代表／一般メンバー）と、代表によるアカウント発行。現在のロールは**管理者とユーザーの2種類のみ** |
| 未実装 | 注文・チャットの自動更新や通知（画面を開き直すと反映） |
| 制約 | ICカードリーダーはローカルPC接続時のみ。クラウド上では使えない |
| 制約 | 英語表示は一部のみ翻訳（未翻訳は日本語のまま表示） |
| 技術的負債 | 自動テストのうち入退室まわり8件が、カード選択必須化の仕様変更に追従できておらず失敗する（アプリの不具合ではなく、テスト側の更新漏れ。画面での動作は確認済み） |
| 資料 | `docs/要件定義書.xlsx`・`docs/設計書.xlsx`は2026-08-31版のままで、チャット・会議室・注文・間取り図などが未反映 |
| デモ環境 | 本番デモのデータはテスト用（会議室5件・メニュー5件・予約5件・注文4件など） |

## 6. 技術構成（要約）

| 層 | 技術 |
| --- | --- |
| 画面 | React（Vite）。QR読取・QR表示、3D表示にそれぞれライブラリを使用 |
| サーバー | Django ＋ Django REST Framework、認証はJWT |
| データベース | 本番はPostgres、開発はSQLite |
| 公開 | Railway（Dockerで画面とAPIを1つのサービスとして配信） |
| 通知 | Webhook（入退室イベントを外部URLへJSONで送信） |

アプリ構成: `accounts`（ログイン・権限）、`members`（会員・プラン・招待）、`access`（入退室）、
`cards`（カード貸出）、`chat`、`meetingrooms`（会議室・予約・間取り図）、`orders`（注文）、`orgsettings`（設定・お知らせ）。
